# Оплата через Kaspi — как это работает

## Как сейчас у MediVitamins

1. Клиент оставляет имя и телефон на сайте.
2. Менеджер пишет в WhatsApp.
3. Вручную выставляет **удалённый счёт** в приложении Kaspi (Kaspi Pay → Выставить счёт → номер клиента → сумма).
4. Клиент подтверждает оплату в Kaspi.kz.

**Минусы:** задержка, клиенты «игнорят», сумма вводится вручную, ошибки в цене.

---

## Что хочет Сымбат (2 варианта на сайте)

| Вариант | Для клиента | Для магазина |
|--------|-------------|--------------|
| **1. Оплатить сейчас** | Сразу переход в Kaspi / push со счётом на **точную сумму корзины** | Меньше ручной работы, выше конверсия |
| **2. Оставить заявку** | «Перезвоните / напишите мне» | Как сейчас — менеджер сам выставляет счёт |

Оба варианта можно сделать на одной странице оформления заказа.

---

## Как технически «перенаправить с ценой на Kaspi»

Сумма **не передаётся просто ссылкой в браузере** (типа `kaspi.kz?amount=15000`) — Kaspi так не работает для ИП/ТОО. Нужен один из путей ниже.

### Путь A — Официальный Kaspi Pay Merchant API (рекомендуется для крупного магазина)

1. Заявка на [kaspi.kz/merchantapi](https://kaspi.kz/merchantapi) (БИН/ИИН, расчётный счёт).
2. После одобрения: `TradePointId`, `ApiKey`, тестовая среда.
3. Сайт при оформлении:
   - создаёт заказ в нашей БД;
   - вызывает API Kaspi: сумма, номер заказа, телефон, `returnUrl` (страница «Спасибо»);
   - получает **ссылку на оплату** или создаёт удалённый счёт;
   - **редирект** клиента: `window.location.href = paymentUrl`.
4. Kaspi шлёт **webhook** «оплачено» → статус заказа `confirmed`, можно собирать посылку.

Документация: [Kaspi Pay API](https://pay.kaspi.kz/api/v2) (после подключения).

**Плюсы:** официально, рассрочка Kaspi Red / 0-0-12, QR.  
**Минусы:** договор с банком, срок подключения 1–2 недели, иногда VPN/IPSec.

---

### Путь B — Платёжный посредник (ApiPay, Pay.Aibot и др.)

Сервис уже подключён к Kaspi Pay от имени магазина.

1. Регистрация у посредника (например [apipay.kz](https://apipay.kz)).
2. Привязка кассира Kaspi (номер ИП + SMS, ~1 мин).
3. API-ключ в `.env` сайта.
4. При оплате: `POST /invoices` — телефон, сумма, корзина → клиенту push в Kaspi или ссылка на оплату.

**Плюсы:** быстрее старт (часы/дни), проще API, вебхуки.  
**Минусы:** комиссия/абонент посредника, зависимость от третьей стороны.

---

### Путь C — «Ссылка от Сымбат» (временное решение)

Если Kaspi или бухгалтерия дали **постоянную ссылку магазина** (редко с фиксированной суммой):

- Кнопка «Оплатить в Kaspi» ведёт на эту ссылку.
- **Сумма в ссылке не подставится автоматически** — клиент видит фиксированную цену или вводит сам.

Подходит только как заглушка, **не заменяет** API для корзины с разными товарами.

## Что запросить у Kaspi (текст для Сымбат)

> Здравствуйте! Нам нужно подключить приём оплаты на интернет-магазине mediavitamins.kz.  
> Нужно: выставление удалённого счёта по API (телефон + сумма заказа), ссылка/редирект на оплату для клиента, уведомление об оплате (webhook).  
> Подскажите, как подключить Kaspi Pay Merchant API / eCommerce, какие документы нужны и контакт менеджера.

## Что уже сделано на сайте

- Заказ сохраняется в MongoDB (`orders`).
- На шаге «Оплата» — выбор:
  - **Kaspi — оплатить сейчас** (редирект, когда появится API-ключ);
  - **Оставить заявку** (успех + WhatsApp с номером заказа и суммой).
- Переменные окружения см. `.env.example` (`KASPI_*`).

После получения ключей от Kaspi или ApiPay — один redeploy, кнопка Kaspi начнёт вести на оплату с правильной суммой.
